# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Stack

Delegated and approved: Vite + React with plain CSS, deployed through GitHub Pages.

## Users

Prospective hackathon participants evaluating an event, exploring challenge tracks, and looking for a team or project direction.

## Product Purpose

Hackthon is a prototype for a future hackathon platform. The first release demonstrates the event story, example challenge tracks, an event journey, featured builds, team matching, and local registration-interest behavior. Success means a visitor can understand the event and explore the prototype in one visit while the owner can replace demo features later without rebuilding the visual foundation.

## Positioning

Hackthon treats a hackathon as a visible creative system: ideas move from challenge to team to prototype to launch within one coherent event journey.

## Operating Context

Visitors use the website on desktop and mobile before an event. They scan tracks, understand milestones, inspect sample projects, preview participant matches, and may record local registration interest.

## Capabilities and Constraints

- Single-page responsive prototype with anchored navigation.
- Local demo data only.
- Browser-calculated event countdown.
- Interactive challenge, timeline, team-match, mobile-navigation, and registration-interest states.
- No authentication, persistence, external APIs, payment, or real form transmission in this version.
- Final product features remain explicitly undecided and will replace the demonstration features later.

## Brand Commitments

- Product and repository name: Hackthon.
- The supplied TikTok landing-page reference is inspiration, not a template to copy.
- The approved product voice is optimistic, concise, inventive, and grounded in making.

## Evidence on Hand

- Approved design specification: `docs/superpowers/specs/2026-10-09-hackthon-design.md`.
- Approved implementation plan: `docs/superpowers/plans/2026-10-09-hackthon-implementation.md`.
- No customer logos, testimonials, performance claims, sponsor marks, or production event data are available; the prototype must not fabricate them.

## Product Principles

- Show the making process instead of merely advertising an event.
- Make every demonstration feature easy to replace.
- Keep the first interaction understandable without instructions.
- Prefer a few polished local interactions over speculative platform breadth.
- Treat mobile and keyboard access as part of the core experience.

## Accessibility & Inclusion

The site must support semantic structure, visible keyboard focus, keyboard-operable controls, readable contrast, 200% text enlargement, reduced motion, and layouts down to 320px wide.
